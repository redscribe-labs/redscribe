# Contributing to RedScribe

Thanks for your interest in RedScribe. Here's how you can help, and how
you can't.

## What's welcome

- **Bug reports.** Use the issue templates under `.github/ISSUE_TEMPLATE/`
  — they ask for the information that's actually useful for reproducing a
  problem in a self-hosted Django app (version, install method, whether it
  reproduces on a clean instance).
- **Feature requests / change requests.** Same place, a separate template.
  Describe what you'd like to see and why — a maintainer will pick it up
  if it's a good fit, on their own timeline.
- **Security reports.** Do **not** open a public issue for a security
  vulnerability in RedScribe itself — see
  [`.github/SECURITY.md`](.github/SECURITY.md) for the private reporting
  process and what's in and out of scope.

## What isn't accepted

**Pull requests aren't accepted.** Every code change to RedScribe — fixes
included — is made by the RedScribe maintainer(s) directly. This isn't a
judgment on the quality of any patch someone might put together; it's a
deliberate choice about how this project is run. If you'd like something
changed, open an issue describing it instead of a PR. A maintainer will
implement it themselves if it's a good fit.

If a pull request is opened anyway, expect it to be closed unmerged and
pointed back here — not reviewed for a possible merge.
